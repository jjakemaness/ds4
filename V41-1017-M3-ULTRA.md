# DeepSeek V4.1 Flash 1017 on a 256 GB M3 Ultra

This branch packages the configuration tested on an 80-GPU-core Mac Studio M3
Ultra with 256 GB unified memory and macOS 27.0.1. It is based on the PR #1073
Metal path at commit `fd70919` and retains its V4.1 decode, prefill, indexer,
DSpark, and asynchronous Engram-read optimizations.

The earlier [`jjakemaness` parallel-Engram change](https://github.com/jjakemaness/ds4/commit/63c595116bfdec4df7687f1e0bb604121c8fa891)
is superseded here by PR #1073's asynchronous implementation: both Engram
tables begin reading before layer 0, each table joins at its consuming layer,
and `ds4_engram_read_batch()` parallelizes from two rows upward.

## Artifacts

The three files must come from the same 1017 checkpoint:

```sh
mkdir -p gguf

hf download antirez/deepseek-v4.1-flash-gguf \
  DeepSeek-V4.1-Flash-1017-IQ2_XXS-Q2_K-imatrix.gguf \
  --local-dir gguf

hf download kyuz0/deepseek-v4.1-flash-gguf \
  DeepSeek-V4.1-Flash-1017-vision-BF16.gguf \
  DeepSeek-V4.1-Flash-1017-DSpark-MXFP4.gguf \
  --local-dir gguf
```

Expected byte sizes:

| Artifact | Bytes |
| --- | ---: |
| Q2 language model | 365,713,686,528 |
| MXFP4 DSpark model | 7,966,294,016 |
| BF16 vision encoder | 970,555,552 |

Do not reuse the September DSpark model, vision encoder, or serialized KV
tensors with 1017. KV values depend on the exact model weights.

## Build

```sh
make -j"$(sysctl -n hw.ncpu)" ds4 ds4-server ds4-agent
```

The vision revision check is adapted from
[`kyuz0/deepseek-v4.1-flash-gguf`](https://huggingface.co/kyuz0/deepseek-v4.1-flash-gguf/blob/main/compatibility/vision-checkpoint-1017.patch)
and selects the encoder revision from the loaded language-model metadata.

## Run

HTTP server:

```sh
./serve-v41.sh
```

Native DwarfStar agent, run from the project it should edit:

```sh
/path/to/ds4/chat-v41.sh
```

The native agent runs inference in-process; it is not an HTTP client. Do not
run it at the same time as `ds4-server`. The launchers enforce that constraint.

Useful overrides:

```sh
NOSPEC=1 ./serve-v41.sh       # compare without DSpark
CTX=524288 ./serve-v41.sh     # larger context
MODEL_DIR=/models/ds4 ./serve-v41.sh
KV_MB=8192 ./serve-v41.sh
```

The server defaults to a checkpoint-specific cache directory:
`~/.ds4/server-kv-v41-1017`. Keep older checkpoint caches separate.

## Tested behavior

The September V4.1 configuration measured about 50 tokens/s on short replies,
about 47 tokens/s near 10K context, and the mid-30s near 115K context with
DSpark. Initial interactive 1017 testing is comparable; a frozen, repeated
benchmark set has not yet been published, so these are setup observations, not
cross-checkpoint quality or performance claims.

Keep Metal residency and queue keepalive at their defaults. Explicitly setting
`DS4_METAL_NO_RESIDENCY=1` or `DS4_METAL_DISABLE_QUEUE_KEEPALIVE=1` caused
multi-minute stalls in this configuration. If the first prefill remains at
zero while one CPU thread spins after several days of uptime, restart macOS to
reset the Metal driver before changing model settings.
